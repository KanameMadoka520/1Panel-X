# Phase 08 Plan 01: Branding Backend Wiring

**Requirement:** BRAND-01

## Steps

1. **`core/app/service/enhancement.go`**
   - Add default consts (empty): none strictly needed; use `""` inline defaults.
   - `GetSettingInfo`: add `Title/MasterAlias/LoginBgType/LoginBackground/LoginBtnLinkColor` via `loadValidatedEnhancementValue("<Key>", "")`.
   - `GetPublicSettingInfo`: add the same five fields (the widened anon subset).
   - `validateEnhancementSetting`: add cases:
     - `"Title"`, `"MasterAlias"`: `validateBrandingText(value, 64)` — allow empty; else reject if `strings.ContainsAny(value, "<>")`, reject control chars (`unicode.IsControl` except none), cap `len([]rune) <= 64`.
     - `"LoginBgType"`: allow `""`, `"image"`, `"color"`.
     - `"LoginBackground"`, `"LoginBtnLinkColor"`: allow `""` else `isSafeCSSColor`.
   - Add helper `validateBrandingText(value string, maxRunes int) error`.

2. **`core/app/dto/enhancement.go`**
   - Add the five fields to `PublicEnhancementSettingInfo` (json: `title, masterAlias, loginBgType, loginBackground, loginBtnLinkColor`).
   - Extend `EnhancementSettingUpdate` `oneof` to include `Title MasterAlias LoginBgType LoginBackground LoginBtnLinkColor`.

3. **`core/app/service/enhancement_test.go`** (extend)
   - Table tests for each new key: valid (incl. empty), and invalid (Title with `<`, control char, 65+ runes; LoginBgType `"nope"`; LoginBackground `"red"`/`"javascript:"`).
   - `TestPublicSubsetIsStrictSubset`: marshal both DTOs to JSON, assert `keys(public) ⊆ keys(authed)` and public has no `watermark`/`title`... wait, public MUST contain the cosmetic keys; assert public contains ONLY {theme,themeColor,title,masterAlias,loginBgType,loginBackground,loginBtnLinkColor} and NONE of {watermark,watermarkShow,logo,favicon,loginImage,logoWithText}.
   - `TestLoadValidatedFallback`: a corrupt stored branding value falls back to `""`.

## Verification

- gofmt/vet clean; `go build ./...` (core).
