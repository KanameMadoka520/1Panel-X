# WAF 专业版功能面对照规格（观察记录）

**日期：** 2026-07-26 · **记录人：** KanameMadoka520 · **分支：** `open-pro-v1`
**来源：** 用户提供的 1Panel 专业版 v2.2.3 面板 WAF 页面截图 10 张（真实运行实例）。

## 来源性质与红线（先读）

本文件记录的是**专业版 WAF 的用户可见界面与行为**——即任何购买者在浏览器里都能看到的公开产品表面。
它**不包含**、也**不得包含**：闭源 `1pwaf` / xpack 的源码、内部实现细节、私有协议、规则库原文。

- 截图里出现的正则规则条目仅作为**规则分类维度的证据**（说明专业版把规则分成哪些组、打什么类型标签），
  **不得**把这些正则抄进我们的规则集冒充自研。我们的引擎是 Coraza v3 + CRS v4，规则来源必须是 CRS 自身。
- 复刻目标是**用户结果**（能做到同类事、信息组织方式可对齐），不是实现同构。
- 任何我们没有真实测量的数字、没有真实执行的规则，**一律不得在 UI 上显示**（见文末「诚实性陷阱」）。

## 顶层结构

专业版 WAF 是**独立一级页面**：左侧主导航 `高级功能 → WAF`（与 APP / 多机管理 / 网站监控 / 资源同步 / AI 建站 / 网站防篡改 / 应用高可用 / 界面设置 并列）。

页面顶部 7 个标签页：

| # | 标签 | 性质 |
|---|---|---|
| 1 | 概览 | 仪表盘（读） |
| 2 | 攻击报表 | 聚合报表（读 + 拉黑动作） |
| 3 | 拦截记录 | 明细日志（读 + 批量动作） |
| 4 | 封锁记录 | 临时封禁台账（读 + 解封/拉黑） |
| 5 | 黑白名单 | 名单管理（写） |
| 6 | 网站设置 | 单站点策略（写） |
| 7 | 全局设置 | 全局默认策略 + 总开关（写） |

我们当前只有「网站详情 → WAF 标签页」（站点级开关/模式/IP 名单/攻击日志），**没有**一级 WAF 页面。

## 4. 封锁记录

- **提示条**：「封锁 IP 临时存储在 OpenResty 中，重启 OpenResty 会解封，可以通过拉黑功能永久拉黑」。
- **操作行**：`清空所有日志`、`批量拉黑 IP`、`批量拉黑 IP 段`、`导出日志`；右侧 IP 搜索框、刷新、`不刷新`、齿轮。
- **表列**：复选框 / `IP` / `时间` / `状态`（`已解封` 绿标签） / `封禁时间`（`10分钟`） / `IP 归属地` / `命中规则` / `操作`（`拉黑` `拉黑 IP 段` `解封` `详情`）。
- 观察到的 `命中规则` 取值：`攻击频率限制`、`404 频率限制`。
- 共 118 条。

> 关键观察：**封禁是有 TTL 的临时状态**，与「黑名单」（永久）是两套东西；封禁记录里的「拉黑」是把临时封禁**升级**为永久黑名单。

- **CDN 面板**（截图详情）：

## 7. 全局设置

- 按钮组：`频率限制` / `默认规则` / `自定义规则` / `配置`。
- **WAF 总开关**卡片：「关闭之后所有网站将失去防护」+ `已启用` + 开关。
- **两级语义提示条**（原文，重要）：
  > 带有【网站】标签的设置，需要在【网站设置】配置生效，全局设置仅为新建网站的默认设置
  > 设置生效需要【全局设置】和【网站设置】的开关同时打开
- 带【网站】标签的设置项旁有 `应用到网站` 按钮（把当前全局值推给已有站点）。

### 7.1 频率限制

左侧四项：`访问频率限制` / `攻击频率限制` / `404 频率限制` / `URL 频率限制`。

`访问频率限制` 面板（截图详情）：
- 标题行 + 开关。
- 人话摘要：「10 秒内累计请求任意网站超过 200 次，封锁此 IP 10分钟」+ `网站` 标签。
- 表单（全部必填 `*`）：`模式`（下拉：`全局模式` / `URL 模式`）、`周期` `10` 秒、`频率` `200` 次、`封禁时间` `600` 秒。
- 按钮：`保存默认`、`应用到网站`。
- 说明：
  - 全局模式：单位时间请求任意 URL 次数之和超过阈值即触发
  - URL 模式：单位时间请求单个 URL 次数超过阈值即触发
  - 封锁 IP 临时存储在 OpenResty 中，重启 OpenResty 会解封，可以通过拉黑功能永久拉黑

### 7.2 默认规则

左侧九组：`参数规则` / `URL 规则` / `HTTP 规则` / `Cookie 规则` / `Header 规则` / `User-Agent 规则` / `补充规则` / `应用规则` / `其他`。

每组面板：组开关 + 一句说明 + `网站` 标签 + `应用到网站` 按钮 + 规则表。
规则表列：`规则`（正则原文）/ `类型` / `备注` / `状态`（每条一个开关）。

观察到的 `类型` 取值集合（重要——这是分类维度的证据）：
`SQL 注入`、`XSS`、`一句话木马`、`目录过滤`、`应用危险目录过滤`、`参数规则`。

- `参数规则` 组说明为「禁止请求中携带恶意参数」，共 8 条。
- `URL 规则` 组说明为「禁止访问的 URL」，共 6 条，类型为 `目录过滤` / `应用危险目录过滤`。

> 关键观察：专业版是**手写正则表 + 逐条开关**。我们是 CRS 规则集，**不能**照抄正则表；
> 对等的诚实做法是暴露 **CRS 规则组（按 tag）+ 按规则 ID 的例外/排除**（见「诚实性陷阱」§R2）。

左侧四项：`自定义规则` / `文件上传限制` / `地区访问限制` / `CDN`。

`自定义规则` 面板：`创建` 按钮 + 说明「根据条件匹配执行相应动作」+ `网站` 标签。
表列：`名称` / `规则` / `动作` / `状态` / `备注` / `操作`。（截图为空表）

## 与我们现状的差异（初判，待代码侦察结论校正）

| 专业版能力 | 我们现状 |
|---|---|
| 一级 WAF 页面（7 标签） | 无，只有站点详情内一个 tab |
| 概览四数字 + 趋势 + 拦截地图 | 无；且**没有总请求/4xx/5xx 计数**（我们只存攻击事件） |
| 攻击报表 TOP IP/URL | 无（事件表可聚合） |
| 拦截记录（过滤/批量/导出） | 有基础事件表，无过滤维度/批量/导出 |
| 封锁记录（临时封禁 + TTL + 解封） | **完全没有**——我们无频率限制、无封禁概念 |
| 黑白名单 IP | **有**（站点级 allow/deny + 全局并入） |
| 黑白名单 URL / User-Agent / IP 组 | 无 |
| 频率限制（4 类 × 模式/周期/频率/封禁时间） | **完全没有** |
| 默认规则分组 + 逐条开关 | 无 UI；引擎侧是 CRS PL1 全量 |
| 自定义规则（条件→动作） | 无 |
| 文件上传限制 | 无 |
| 地区访问限制 | 无（但 `agent/utils/geo` 已有 mmdb 能力） |
| CDN 真实 IP 头列表 | **部分**——网关只支持单个 header（`WithRealIPHeader`） |
| 两级（全局默认 → 站点覆盖）+ 应用到网站 | **有**两级（模式 + IP 名单）；无「应用到网站」推送动作 |
| WAF 总开关 | 无（我们只有逐站点开关） |

## 诚实性陷阱（实现时逐条守）

- **R1 假统计**：概览的 `请求` / `4xx` / `5xx` 是**全量流量统计**。我们的攻击事件表只有被拦/被记的请求。
  → 要么接入真实的全量计数（网关侧计数器或复用 `website_stat.db` 的访问日志聚合），**要么这几个卡片不做**。
  绝不能拿攻击事件数冒充请求数。
- **R2 假规则表**：绝不能把专业版截图里的正则抄成一张「我们的规则表」摆在 UI 上——那既是抄闭源产物，
  又与我们实际执行的 CRS 规则**不一致**（显示的和拦的不是一回事 = 假功能）。
  诚实做法：展示**真实生效的 CRS 规则组/标签**，开关真实映射到 Coraza 的规则移除/排除指令，并在 UI 明示规则来源是 OWASP CRS v4。
- **R3 假封禁语义**：专业版的「临时存储在 OpenResty 中，重启会解封」是**它的**实现语义。
  我们的封禁在 `coraza-gateway` 里，重启行为由我们决定 → UI 文案必须描述**我们**的真实行为，不得照抄这句话。
- **R4 假地图**：拦截地图需要真实的 IP→国家解析。mmdb 缺失时必须优雅降级（显示「未启用地理库」），不得造点。
- **R5 假总开关**：「WAF 总开关」若做，必须真的让所有站点失去防护（真实改配置/翻路由），
  不能只是一个前端布尔值；且关闭后站点状态必须如实显示为未防护。
- **R6 假「应用到网站」**：该按钮必须真的把全局值写进各站点策略并重生成网关配置 + 等待 generation 就绪，
  失败要回滚并如实报错，不能只弹一个成功提示。
- **R7 人工 UAT**：本文件涉及的所有浏览器交互、真实流量拦截、封禁/解封、频率触发，
  在没有真机证据前一律标 `pending` / `human_needed`，自动化测试通过 ≠ 人工验收通过。

## 频率限制四项的真实形态（重要：四项形状各不相同）

| 项 | 【网站】标签 | 字段 | 按钮 |
|---|---|---|---|
| 访问频率限制 | **有** | 模式（全局模式/URL 模式）· 周期 10 秒 · 频率 200 次 · 封禁时间 600 秒 | 保存默认 + **应用到网站** |
| 攻击频率限制 | 无 | 周期 60 秒 · 频率 60 次 · 封禁时间 600 秒 | 仅**保存** |
| 404 频率限制 | 无 | 周期 10 秒 · 频率 30 次 · 封禁时间 600 秒 | 仅**保存** |
| URL 频率限制 | 无 | **列表型**：创建 + 总开关 + 表（URL / 配置 / 状态 / 操作） | 每行增删改 |

- 摘要文案：攻击=「60 秒内累计**拦截**超过 60 次，封锁此 IP 10分钟」；404=「10 秒内累计请求返回 404 超过 30 次…」。
- 全部字段带红星必填，**没有**「0 = 只记录不封禁」这种模式（对齐待办 A6 成立）。
- **URL 频率限制是一组按 URL 配置的条目，不是单一阈值**——与我方现有的「单条 url 类型限制」形状不同，属新增差异（见 A9）。

## 默认规则各组的真实内容

- **HTTP 规则** = **HTTP 方法白名单**。说明原文：「设置允许访问的方法类型，如果想限制某些类型访问，请关闭这个类型的按钮，例如：仅允许 GET 类型访问，那么需要关闭除了 GET 之外的其他类型按钮」。
  即**开 = 允许，关 = 拒绝**。表列 规则 / 类型（恒为「HTTP 方法过滤」）/ 备注 / 状态。
  观察到的方法（顺序即界面顺序）：`GET POST PUT DELETE PATCH HEAD OPTIONS TRACE CONNECT … MKCOL COPY MOVE LOCK UNLOCK LINK UNLINK WRAPPED SRARCH`
  （`SRARCH` 疑为官方拼写错误，正常应为 `SEARCH`；复刻时用正确拼写并记录此差异。）
- **其他** = 三个开关，各带一句说明：
  - `SQL 注入防御` — 识别请求中的 SQL 注入并拦截
  - `XSS 防御` — 识别请求中的 XSS 并拦截
  - `严格模式` — 使用更严格的规则来校验请求
  → 这三项正好能映射到 CRS 的原生旋钮（SQLi/XSS 规则段 + paranoia level），**比第一批推测的「9 组规则目录」更贴近官方，且我方可诚实实现**。
- **应用规则** = 按应用降误报的规则集。说明原文：「常见应用的规则，开启之后可以减少误报，**一个网站只能使用一个规则**」。
