# 研究摘要

## 结论

1Panel 的商业能力不是一个可以一次替换的单模块，而是覆盖 core、agent、前端、独立数据库和构建标签的多个安全域。最可靠的路线是从公开接口中的单点空实现入手，建立开放扩展模式，再逐步处理多节点、WAF、RBAC 等跨模块能力。

## 首版选择

- 自定义主题与水印：用户价值直接，依赖少，可建立开放设置模式。
- 企业微信/钉钉/飞书 Webhook：公开协议明确，现有告警模型完整。
- ClamAV 定时扫描：扫描、记录、UI 和告警已公开，缺口集中在调度。
- AI Agent 默认不限数量：现有完整生命周期已公开，只有版本绑定的硬上限。

## 关键技术决策

- 不伪造许可证、不全局开启 Pro 状态。
- 保留 `upstream/dev-v2` 历史，在 `open-pro-v1` 小步提交。
- 前端生产构建使用 `npm ci && npm run build:pro`。
- Go 统一使用 1.26.1 的 Linux 工具链验证 core 和 agent。
- 第一版输出原生 Linux 二进制发布包；Docker 用于可复现构建，不作为默认运行隔离层。

## 最大风险

- WAF、多节点、RBAC、防篡改、数据库高可用、AI 网关和虚拟机不能用空页面或假数据宣称完成。
- 当前仓库几乎没有行为测试；所有新能力必须自带测试。
- 完整独立安装层不在源码仓库中，首轮 VPS 验证需要基于同版本官方安装骨架替换二进制。

## 推荐里程碑

1. v0.1 开放增强基础：本轮四项功能、测试、构建包和 VPS 替换说明。
2. v0.2 安全与监控：WAF 增强、站点监控、代理/应用仓库、模型下载器。
3. v0.3 多节点与权限：节点协议、同步、资源总览、RBAC。
4. v0.4 运维平台：防篡改、运维报表、Skills Hub、基准测试。
5. v1.0 高风险域：数据库高可用、完整 AI 网关、虚拟机和独立安装升级器。
