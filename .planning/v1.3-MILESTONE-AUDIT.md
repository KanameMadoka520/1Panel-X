## Security posture (adversarial review — passed)
Workflow `wf_cdaea91b-aad`: 7 independent security lenses (serve-XSS T1/T2, upload-decode T1/T5/T10, path/fs T3/T6, DoS T4, anon-leak T8, CSRF/authz T9, logic-correctness) each returned **no findings**; a completeness critic raised 7 hygiene notes, **all adversarially refuted as not-a-bug** (every vector neutralized by an existing control). Three were adopted as non-security quality polish (decode-comment precision, serve/upload allowlist parity, frontend accept-list alignment).
- **T1/T2:** serve route no longer force-serves `<svg>`; fixed raster Content-Type + `X-Content-Type-Options: nosniff`; fixed-enum + regular-file gate. A stored PNG-with-trailing-markup is served as `image/png`, never executed.
- **T3/T6:** fixed server-side asset enum → hardcoded basename; atomic temp+rename with prefix assert; reset targets the exact basename (no glob).
- **T4/T5:** `MaxBytesReader` before parse + per-asset byte cap; `DecodeConfig` dimension cap (≤16 MP) before full `Decode`.
- **T8:** anon subset widened only with cosmetic presence sentinels for images already anonymously served; watermark/paths/bytes/versions excluded, proven by the subset test.
- **T9:** write routes behind SessionAuth + PasswordExpired + the global `CSRFTokenGuard`; image keys absent from the text update `oneof`.
- **T10:** favicon PNG-only (no stdlib `.ico` decoder).
